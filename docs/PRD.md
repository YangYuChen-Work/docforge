# 场景1文档生成 POC 产品需求文档

## 1. 文档目的

本 PRD 用于指导 Claude Code 或其他 AI 开发代理理解业务目标、功能边界、领域对象和验收标准，建设一个轻量的本地文档生成 POC。

本 POC 不是继续完善静态演示，而是将“场景1文档生成”做成具备真实后端、本地数据库、真实文件解析和 AI 生成能力的可运行系统。

## 2. 产品定位

产品名称暂定：项目文档生成工作台。

产品定位：

> 面向产品研发人员的本地项目文档生成与追溯工具。用户选择项目和标准模板，系统关联项目资料、历史文档和结构化数据，按章节生成规范化项目文档，并保留来源、版本和人工确认记录。

## 3. POC 目标

### 3.1 必须实现的目标

1. 使用 `reference/demo-platform/doc-data.js` 中的项目数据作为项目列表种子数据。
2. 使用真实的场景1来源资料进行解析。
3. 使用真实的 Word 目标模板保持文档章节和基础表格结构。
4. 完成一次真实的“项目 + 模板 + 资料 → DOCX 文档”生成闭环。
5. 每个生成章节能够显示引用来源或待补充状态。
6. 用户可以对章节进行人工确认、重新生成和导出。
7. 生成、解析、修改、导出和失败过程可查询。

### 3.2 不在当前 POC 范围内

- 多用户登录、组织架构和复杂权限。
- 多租户、企业级部署和高并发。
- 微服务、Redis、消息队列、向量数据库。
- 测试用例生成的真实后端能力。
- 产品模块智能选配和 BOM 的真实后端能力。
- 自动替代工程师完成最终审批。
- 自动编造来源资料中不存在的产品参数。

## 4. 用户与角色

当前 POC 为单用户本地使用，但业务上保留以下角色概念：

| 角色 | 主要职责 |
|---|---|
| 产品/项目负责人 | 创建项目、选择模板、确认生成范围和最终内容 |
| 专业工程师 | 提供市场、技术、质量、制造、采购等专业资料，修改章节内容 |
| 文档管理员 | 维护模板、章节规则和标准文档格式 |
| 评审人员 | 查看引用、检查内容、提出修改意见、确认文档 |

## 5. 核心用户故事

### 5.1 选择项目和模板

作为项目负责人，我希望从项目列表选择一个研发项目，再选择适合当前研发阶段的标准文档模板，以便生成正确类型的项目文档。

验收标准：

- 页面显示 Demo 中的项目数据，包括项目名称、项目编号、产品型号和研发阶段。
- 模板按类别和适用阶段展示。
- 用户选择项目和模板后可以看到生成前确认信息。
- 不允许在未选择项目或模板时创建生成任务。

### 5.2 关联真实来源资料

作为项目负责人，我希望上传或选择本地来源资料，并将其关联到项目，以便系统基于真实资料生成内容。

验收标准：

- 支持 DOCX 和 XLSX 文件。
- 记录原始文件名、文件类型、大小、哈希、上传时间和解析状态。
- 原始文件不被覆盖。
- 解析失败时显示失败原因，并允许重新解析。
- 可以看到一个项目已关联的资料清单。

### 5.3 按章节生成文档

作为项目负责人，我希望系统按模板章节生成文档，而不是只生成一段不可追溯的长文本。

验收标准：

- 生成任务有明确状态：待处理、解析中、生成中、待确认、已完成、失败。
- 每个章节独立记录生成状态。
- 章节可以显示使用了哪些来源文件。
- 来源资料不足时显示待补充项。
- AI 不能将未知内容写成确定事实。

### 5.4 人工确认和重新生成

作为工程师，我希望修改某一章节或重新生成某一章节，而不是每次都重新生成整份文档。

验收标准：

- 支持查看章节正文、表格和引用。
- 支持人工编辑章节内容。
- 支持针对当前章节补充指令并重新生成。
- 重新生成前保留当前版本。
- 用户可以确认章节或标记为待补充。

### 5.5 导出规范化文档

作为项目负责人，我希望导出的 Word 文档保留目标模板的章节结构和基础格式，以便直接作为项目文档继续使用。

验收标准：

- 能生成可打开的 DOCX。
- 输出文件不覆盖原始模板。
- 输出文件记录生成时间、项目、模板和版本。
- 导出失败时保留错误信息，不显示虚假的成功状态。

## 6. 功能需求

### P0-1 项目管理

项目页面参考 `reference/demo-platform/doc-assistant.html` 的布局，但采用工程管理风格。

字段：

- 项目 ID
- 项目名称
- 项目编号
- 产品型号
- 产品类别
- 当前研发阶段
- 项目状态
- 关联资料数量
- 已生成文档数量

POC 种子数据必须来自 `DOC_PROJECTS`：

| ID | 项目名称 | 编号 | 型号 | 阶段 |
|---|---|---|---|---|
| P001 | 80t 汽车起重机臂架优化项目 | XG-ZX-2026-042 | XCT80L7 | 方案设计 |
| P002 | 全地面起重机液压系统升级项目 | XG-ZX-2026-031 | XCA130 | 需求冻结 |
| P003 | 履带起重机转台结构轻量化项目 | XG-ZX-2025-118 | XGC260 | 试制验证 |
| P004 | 起重机智能安全监测系统 | XG-ZX-2025-096 | XCT55L6 | 详细设计 |
| P005 | 新能源动力底盘适配项目 | XG-ZX-2025-071 | XCA60_EV | 前期调研 |

### P0-2 模板管理

POC 初始模板种子数据可以来自 `DOC_TEMPLATES`，但场景1必须支持真实 Word 模板。

模板字段：

- 模板 ID
- 模板名称
- 适用阶段
- 模板类别
- 章节数量
- 模板文件路径
- 模板版本
- 是否启用
- 章节生成说明

初始模板包括：总体设计方案、产品设计任务书、结构设计说明书、液压系统设计说明书、市场需求分析报告、试制验证方案、设计评审材料。

### P0-3 来源资料管理

来源资料页面需要支持：

- 上传文件
- 查看文件信息
- 解析文件
- 查看解析结果
- 关联项目
- 查看资料类型
- 查看解析失败原因
- 移除项目关联，但不删除原始文件

支持的 POC 文件类型：

- `.docx`
- `.xlsx`

解析结果至少包括：

- 段落文本
- 标题层级
- 表格标题
- 表头
- 表格行列数据
- 图片是否存在
- 原始文件页/章节信息（能提取时记录）

### P0-4 生成任务

生成任务创建条件：

- 已选择项目
- 已选择模板
- 至少关联一份来源资料

生成任务创建后执行：

1. 检查模板和源文件可用性。
2. 解析未完成的来源资料。
3. 将模板章节与来源资料建立匹配关系。
4. 生成章节级上下文。
5. 调用 AI 生成章节内容。
6. 记录引用和待补充项。
7. 合并到 Word 模板。
8. 生成可下载的 DOCX。

### P0-5 章节匹配

章节匹配结果：

- 已匹配：来源资料充分。
- 部分匹配：已有部分资料，但仍需补充。
- 未匹配：没有找到相关资料。
- 冲突：多份资料对同一事实给出不同内容。

匹配规则优先级：

1. 用户明确指定的资料。
2. 模板章节配置的资料类型。
3. 文件名、标题和章节关键词匹配。
4. 文本内容关键词匹配。
5. AI 辅助判断。

### P0-6 AI 生成

当前 POC 的真实 AI Provider 为 DeepSeek V4 Pro。Provider 通过配置切换，默认模型标识为 `deepseekv4-pro`；API 地址和密钥从环境变量或本地未提交的 `.env` 文件读取。没有密钥时使用 Mock Provider，不阻塞业务流程开发和自动化测试。

AI 每次章节生成必须返回结构化结果：

```json
{
  "chapter_id": "market_analysis",
  "content": "章节正文或结构化内容",
  "citations": [
    {
      "source_document_id": "source-001",
      "locator": "表1 / 第2行",
      "quote_or_summary": "来源内容摘要"
    }
  ],
  "missing_information": [
    "下一年度销量预测"
  ],
  "conflicts": [],
  "confidence": "medium"
}
```

AI 生成原则：

- 只使用当前任务允许的来源资料。
- 对无法从资料推导的事实标记待补充。
- 不允许伪造型号、价格、法规、销量、质量指标或技术参数。
- 生成内容必须能回到来源文件。
- 计算结果必须标明是来源值、推导值还是人工输入值。
- 对冲突资料必须展示冲突，不得静默选择。

### P0-7 文档查看与编辑

界面可参考 Demo 的三栏布局：

- 左侧：文档目录和章节状态。
- 中间：正文、表格和待补充项。
- 右侧：引用来源、生成说明、修改记录和章节操作。

视觉要求：

- 产品名称使用“项目文档工作台”或“项目文档助手”，弱化“AI”作为视觉主标题。
- 不使用机器人、魔法、发光渐变、夸张智能卡片等 AI 营销元素。
- 使用白色、浅灰、深蓝和状态色构成工程管理界面。
- 蓝色表示当前操作，绿色表示完成，橙色表示待确认，红色表示错误或冲突。
- 页面重点突出资料、章节、引用和状态，而不是“AI 能力展示”。

### P0-8 版本、审计和导出

需要记录：

- 创建生成任务
- 上传资料
- 解析资料
- AI 生成章节
- 章节重新生成
- 人工修改
- 章节确认
- 导出文档
- 失败和错误

POC 可以不做完整权限，但必须保留操作人字段，默认值为本地用户。

## 8. 非功能需求

- 本地启动，默认不依赖外部云数据库。
- 源文件和生成文件路径可配置。
- 解析失败、模型失败、导出失败都要可诊断。
- 相同文件重复上传时通过哈希识别，避免无意义重复解析。
- 用户刷新页面后，任务状态仍可从 SQLite 恢复。
- 生成文档必须能用常见 Word 软件打开。
- 所有外部 AI 调用必须通过统一适配层，便于切换真实 API 和 Mock 模式。
- DeepSeek 密钥不得写入代码、数据库、日志、测试文件、截图或导出的 DOCX。
- AI Provider 失败时必须保留失败状态、错误信息和重试入口，不得显示假成功。

## 9. POC 验收标准

给定 Demo 项目 P001、场景1真实资料包和真实 Word 模板：

1. 能创建生成任务。
2. 至少 10 个 DOCX 和 2 个 XLSX 能完成解析或明确报告失败。
3. 目标模板章节能够显示资料匹配状态。
4. 至少生成 3 个有来源引用的章节。
5. 资料不足的章节出现待补充项。
6. 能重新生成单个章节并保留旧版本。
7. 能导出一个可打开的 DOCX。
8. 页面能查看任务状态、生成结果、引用和错误日志。
9. 不覆盖原始模板和源文件。
10. 测试或 Mock 模式不能绕过真实业务状态机。
