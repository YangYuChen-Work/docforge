# 章节来源文件名标记与双向联动设计

## 目标

完善文档编辑器中章节引用的可追溯交互：

1. 正文中引用的表格、图片或其他来源片段显示具体来源文件名。
2. 鼠标悬停来源标记时显示完整文件名提示。
3. 点击正文来源标记后，右侧“数据来源”自动打开对应来源卡片，滚动到可见区域并闪烁提示。
4. 点击来源卡片或“定位正文”后，正文仍能定位引用片段，右侧卡片同步保持高亮。

## 范围与边界

### 包含

- 继续使用现有 Tiptap/ProseMirror 装饰层渲染来源标记，不修改章节 `content_json`。
- 将已加载的来源资料原始文件名注入章节引用装饰数据。
- 来源标记显示完整文件名，`title` 和 `aria-label` 同样提供完整文件名。
- 右侧来源卡片增加稳定的引用 key 和 DOM 定位属性。
- 正文标记、来源卡片和“定位正文”统一通过 `DocEditor` 编排。
- 卡片定位时增加一次性的闪烁动画，同时保留当前卡片选中态。

### 不包含

- 不新增或修改数据库表、Citation 字段或后端 API 协议。
- 不把来源文件名写入正文节点、章节 JSON、DOCX 或 PDF。
- 不改变来源片段匹配规则；没有 `source_excerpt` 或找不到精确片段时继续使用现有回退提示。
- 不实现图片 OCR、表格单元格级的新定位能力；这属于后续来源解析增强。

## 方案选择

### 方案 A：前端引用数据补全与卡片联动（采用）

复用当前 `getSource` 返回的来源详情，在 `DocEditor` 计算章节引用时补充文件名；装饰层负责显示文件名和悬停提示，来源面板负责卡片滚动与闪烁。该方案不改变后端契约，改动集中在现有编辑器联动边界内。

### 方案 B：后端引用接口直接返回文件名

在章节引用 API 中联表返回 `original_name`。前端实现更直接，但会扩大 API 响应契约，并且仍需要前端实现卡片定位和闪烁；当前已有来源详情加载能力，因此不采用。

### 方案 C：将来源文件名写入正文节点

把来源标签作为正文节点或文本 mark 保存。该方案会污染用户编辑内容，可能进入 DOCX/PDF 导出，也会破坏当前“装饰层不持久化”的边界，因此不采用。

## 交互与数据流

```text
章节 citations + sourceDetails
        │
        ▼
DocEditor.chapterCitations（补充 fileName）
        │
        ├── ContentPanel → ReferenceDecorations
        │                 → 正文来源标记/悬停提示
        │                 → 点击 emit citationSelect
        │
        └── AiPanel → 来源卡片 data-citation-key
                    → scrollIntoView + flash
```

正文来源标记点击后，`DocEditor` 设置 `activeCitationKey`、打开来源页签，再调用 `AiPanel` 暴露的卡片聚焦方法。来源卡片点击时沿用现有的正文定位流程，并额外触发卡片聚焦，保证双向联动的视觉反馈一致。

来源详情尚未加载时，标记暂时使用 `来源资料 <source_document_id>` 作为安全回退；详情加载完成后，响应式引用数据会刷新为真实原始文件名。来源详情请求失败不显示假文件名，继续使用来源 ID 和已有引用摘要。

## 组件职责

- `DocEditor.vue`：合并章节引用与来源文件名；维护 active citation；协调正文选择、右侧页签和卡片聚焦。
- `ReferenceDecorations.ts`：接受 `fileName`，生成来源高亮和完整文件名 widget，不写入正文文档。
- `ContentPanel.vue`：保留正文定位与来源装饰样式，适配较长来源标签。
- `AiPanel.vue`：为来源卡片提供 `data-citation-key`，实现卡片滚动、选中和一次性闪烁。
- `page-doc.css`：增加来源标记的长文本布局和来源卡片闪烁动画。

## 失败与降级

- 来源详情加载失败：卡片显示来源 ID、定位和引用摘要，不显示虚构文件名。
- 引用没有 `source_excerpt`：不添加虚假的正文高亮，使用现有“未找到精确片段”的正文定位提示。
- 快速切换章节：`DocEditor` 继续以当前章节 ID 校验异步结果，避免旧章节的文件名或卡片状态串入当前章节。
- 闪烁动画不影响 active 状态；用户点击卡片后仍保持高亮。

## 验收与测试

- 前端静态测试验证引用装饰使用文件名、来源卡片具备稳定定位属性和闪烁调用。
- `npm run build` 验证 Vue 模板、TypeScript 类型和 Vite 构建。
- 运行现有前端 Node 测试。
- 手动浏览器验收：正文来源标记显示文件名；悬停显示完整提示；点击标记后右侧卡片滚动并闪烁；点击卡片后正文定位并同步高亮。
