# 文档编辑器手动保存与快捷键设计

日期：2026-08-10

## 目标

让生成后的文档可以随时修改并保存最新版本，同时保留现有自动保存能力。用户可以通过章节栏的“保存”按钮或 Ctrl+S/Cmd+S 立即保存当前章节；没有新的修改时，保存按钮不可重复点击。

## 已确认范围

- 生成完成后的章节继续保持可编辑，不因章节已确认而锁定。
- 保留现有约 1 秒防抖自动保存作为兜底。
- 手动保存、自动保存和 Ctrl/Cmd+S 使用同一套保存逻辑。
- 保存成功后按钮禁用；当前章节再次发生编辑后按钮恢复可用。
- 保存失败时保留未保存状态，按钮恢复可用并显示错误状态。
- 切换章节前先处理当前章节尚未落盘的修改，避免快速切换造成错存。
- 沿用现有章节编辑接口，不增加数据库字段或新 API。

## 方案

采用前端保存快照方案。编辑器页面维护当前章节的已保存内容快照、待保存内容和保存状态。只有待保存内容与已保存快照不一致时才调用现有 `editChapter` 接口，后端继续负责写入章节内容和版本快照。

相比增加后端内容哈希或改为纯手动保存，该方案改动范围小，兼容当前自动保存行为，也能满足按钮禁用和快捷键交互。

## 组件与职责

### `DocEditor.vue`

- 维护当前章节的保存快照、待保存 payload、保存状态和错误信息。
- 提供统一的 `saveCurrentChapter`，供自动保存、手动按钮和快捷键调用。
- 编辑发生时标记未保存并安排防抖自动保存。
- 切换章节前保存旧章节的待保存内容，再加载新章节并重置快照。
- 在挂载时注册 Ctrl+S/Cmd+S，在卸载时移除监听。

### `ContentPanel.vue`

- 在章节操作栏增加“保存”按钮。
- 接收是否有未保存修改、是否正在保存等展示状态。
- 只有存在未保存修改且当前不在保存中时启用按钮。
- 点击按钮只发出保存事件，不直接处理 API。

### `OutlinePanel.vue`

- 继续展示已保存、保存中和最近保存时间。
- 复用页面传入的保存状态，不承担保存逻辑。

### `app/api/documents.py` 与 `app/domain/documents.py`

- 本次不改接口和领域逻辑。
- 现有 `edit_chapter` 作为唯一章节内容落盘入口。

## 状态与数据流

1. 加载章节后，用返回的 `plain_text` 与 `content_json` 初始化已保存快照；状态为“已保存”。
2. 编辑器更新时缓存章节 ID、文本和 JSON 内容。内容不同于快照时标记为未保存，并启动或重置 1 秒自动保存计时器。
3. `saveCurrentChapter` 开始时捕获章节 ID 和 payload，清除自动保存计时器并标记“保存中”。没有未保存内容时直接返回。
4. API 成功后，将 payload 设为新的已保存快照，清除未保存标记，更新保存时间并显示“已保存”。
5. API 失败后，不更新快照，保留未保存标记，显示错误并允许再次保存。
6. 章节切换先等待当前章节的保存流程完成，再切换 ID、加载内容和重置保存状态。

为避免防抖回调读取已经切换后的章节，自动保存任务必须携带触发时的章节 ID和 payload，不能只依赖可变的当前章节引用。

## 界面行为

保存按钮放在当前章节标题栏，与“确认章节”“重新生成”“导出”并列：

- 有未保存修改：按钮可点击，文案为“保存”。
- 已保存或保存中：按钮禁用。
- 保存失败：按钮恢复可点击，左侧保存状态显示失败信息。

全局快捷键处理 Ctrl+S 和 Cmd+S，阻止浏览器默认网页保存行为，并调用同一个保存函数。若事件目标是文档名称输入框、textarea 或 select，则不拦截，避免影响重命名和表单操作。

## 异常处理

- 没有当前章节、没有待保存内容或已有保存请求时，保存函数无操作。
- 保存请求失败时不丢弃编辑器内容，也不把失败内容标记为已保存。
- 章节切换保存失败时停留在当前章节，并保留可重试状态。
- 组件卸载时清理自动保存计时器和快捷键监听。

## 验证计划

- 前端 TypeScript 类型检查和生产构建。
- 保存状态行为：编辑后按钮可用，保存成功后禁用，再次编辑后恢复可用。
- Ctrl+S/Cmd+S 触发保存并阻止默认行为。
- 保存失败后未保存状态和重试能力仍存在。
- 快速切换章节时，待保存内容写入原章节。
- 运行现有后端测试，确认章节编辑和版本记录无回归。
