# PDF 与 XLSX 导出优化设计

## 目标

完善项目文档的 PDF 与 XLSX 导出，使导出内容与 Web 编辑器中的文档结构保持一致，同时让 XLSX 适合继续编辑、筛选和复用。

范围只包含导出文件的生成和质量验证，不改变文档编辑器、章节确认流程和导出入口。

## 设计决策

### PDF

继续使用现有的 DOCX 模板渲染后通过 LibreOffice 转换 PDF。这样可以复用现有模板的中文字体、页眉页脚和分页能力，避免引入新的 HTML/PDF 渲染运行时。

渲染器负责把 Web 编辑器使用的 ProseMirror 内容映射为文档结构：

- 章节标题和正文保持明确的层级与间距。
- 粗体、斜体、高亮、项目符号、表格等常用内容保留样式。
- 表格使用统一边框、表头强调、合理的列宽和单元格换行。
- 待补充项和内容冲突以醒目的提示段落输出，避免与正文混淆。
- 无模板时使用统一的 A4 文档样式作为兜底。

PDF 只导出文档正文，不导出 Web 页面中的导航栏、AI 助手面板和编辑操作控件。页眉、页脚、页码沿用模板配置；无模板时由兜底样式提供基础页码和文档标题。

### XLSX

XLSX 面向可编辑的结构化数据，而不是像素级复刻 Web 页面。工作簿固定使用以下布局：

1. `项目概览`：文档标题、项目编号、模板名称、导出时间、文档状态，以及待补充项/冲突摘要。
2. `文档目录`：章节名称、表格数量、对应 Sheet 名称。
3. 每个结构化表格一个 Sheet：Sheet 标题、来源章节、表头和数据行。

每个表格 Sheet 应具备：

- 表头加粗、底色、边框和自动筛选。
- 冻结首行，数据区域启用自动换行。
- 根据内容设置列宽并限制最大宽度，避免超长文本撑破布局。
- 保留数字、日期和布尔值的数据类型；空值保持为空。
- 处理重复、非法或超过 Excel 31 字符限制的 Sheet 名称，并保持目录中的映射准确。
- 通过打印设置提供横向打印、适合页宽和重复表头。

没有结构化表格时，生成 `无表格数据` 说明页，明确告知用户当前文档没有可导出的表格。

## 数据流

导出 API 继续接受 `docx`、`pdf`、`xlsx` 三种格式。PDF 复用 DOCX 渲染结果后转换；XLSX 直接从章节的 `content_json` 表格节点生成工作簿。导出记录继续保存生成路径、文件大小、状态和错误信息。

## 错误处理

- 无效的章节 JSON、空章节或无表格内容不得导致整个 XLSX 导出崩溃；应降级为说明内容并保留其他章节。
- LibreOffice 不可用时，PDF 导出返回明确的安装或配置提示。
- 导出失败时保留 `Export` 记录及错误信息，不产生可下载的“完成”状态。
- 文件名和 Sheet 名称使用稳定、可读且经过清洗的值。

## 验证

- 增加/更新 DOCX 渲染测试，覆盖标题、正文、列表、表格、提示内容和空内容兜底。
- 使用 openpyxl 重新打开 XLSX，检查 Sheet 顺序、关键单元格值、样式、冻结窗格、筛选和打印设置。
- 生成真实 PDF，使用 `pdfinfo`/文本提取检查页数与关键内容，再将页面渲染为 PNG 检查分页、中文、表格和提示框是否清晰、无裁切和重叠。
- 运行前端构建和完整 Python 测试套件。
