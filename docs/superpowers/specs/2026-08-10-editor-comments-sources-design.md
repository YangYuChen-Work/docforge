# 文档编辑器批注与来源联动设计

## 目标

完善生成文档编辑页的人工审阅能力：

1. 待补充信息只作为编辑器下方的工作提示，不进入 DOCX/PDF 正文。
2. 用户可以选中文字创建批注，正文显示批注标识；点击标识后，右侧显示批示内容，同时正文对应原文高亮。
3. 用户可以查看当前章节最终使用的全部来源。来源以尺寸一致的卡片展示，卡片标题栏显示文件名称，卡片内容显示定位和参考原文；长内容支持展开查看。
4. 批注、来源卡片与正文互相联动；数据链追踪先保留功能栏位置，不实现实际一致性分析。

## 范围与边界

### 包含

- 右侧功能栏：AI 助手、批注、数据来源、数据链追踪。
- 使用已有 `Annotation.target_text` 保存批注所对应的正文原文。
- 使用已有 `Citation` 记录章节来源文件、定位和参考原文。
- 正文内显示非正文性的批注/来源装饰标记，不将这些 UI 装饰写入生成文档。
- AI 根据批注原文和批示内容生成修改建议，复用现有 AI 结果的替换选区/插入光标操作。
- 来源卡片点击正文定位；正文无法精确匹配来源摘要时，回退到当前章节正文范围并给出明确提示。

### 不包含

- 重新设计批注或引用的数据库模型。
- 将批注、来源卡片、AI 助手或数据链面板导出到 DOCX/PDF。
- 数据链追踪的一致性计算、冲突判断或后端数据链路接口。
- 多人协作、权限和批注审批流。

## 交互设计

### 待补充提示

`missing_information_json` 仍保存在章节数据中，并继续参与导出前校验和导出记录摘要。编辑页将其放在富文本编辑器之后的独立提示区，和正文编辑区域分离。DOCX/PDF 渲染只使用正文节点，不追加“待补充”提示段落。

### 批注

1. 用户在正文选中文字后打开“批注”功能栏。
2. 批注栏提供“为当前选区添加批注”，表单展示选中的原文并填写批示内容。
3. 保存时调用现有批注接口，提交 `target_text`、`content`、`type` 和 `label`。
4. 正文装饰层根据 `target_text` 定位原文：原文使用批注高亮，目标范围末尾显示编号标识。
5. 点击正文编号标识，批注栏切换到对应批注，原文保持高亮；点击批注卡片也会定位正文原文。
6. 批注卡片提供“让 AI 根据批注修改”入口，调用现有章节 AI 操作，并把批注原文作为选区交给 AI。AI 返回结果后仍由用户选择替换原文或插入光标处。
7. 批注保留现有“标记已处理/忽略”状态能力。

### 数据来源

1. 数据来源栏只展示当前章节 `citations` 中的最终来源，不展示未被章节引用的项目资料。
2. 每张卡片使用统一布局和最小高度：
   - 标题栏：来源文件名称。
   - 元信息：具体来源定位（章节、表格、行列等，缺失时显示“未提供定位”）。
   - 参考原文：来源摘要或原文片段。
   - 长内容：默认截断，提供“展开详情/收起详情”。
3. 点击来源卡片或“定位正文”按钮，正文装饰层优先查找 `source_excerpt` 的可匹配片段，找到后选中并滚动到该范围；找不到时定位到当前章节正文，并显示“来源原文未在正文中找到精确片段”的状态。
4. 正文中可显示来源编号装饰标识。来源装饰只存在于编辑器视图，不保存为正文内容，也不进入导出文件。

### 数据链追踪

保留“数据链追踪”功能栏，显示“功能预留，暂未实现”的明确占位说明，不调用接口、不制造一致性结果。

## 技术设计

### 前端组件边界

- `AiPanel.vue`：负责右侧功能栏切换、批注卡片、批注创建表单、来源卡片和数据链占位内容。
- `ContentPanel.vue`：负责富文本正文、缺失提示位置、批注/来源装饰层，以及从外部请求正文定位。
- `DocEditor.vue`：负责加载章节引用、来源文件元数据、创建批注、当前批注/来源状态和组件之间的事件编排。
- `frontend/src/api/sources.ts`：复用/补充来源详情请求。
- `page-doc.css`：统一右侧栏、批注卡片和来源卡片的尺寸、展开状态与装饰标记样式。

正文装饰采用 Tiptap/ProseMirror decoration，不改变 `content_json` 的正文节点。这样用户编辑和导出仍以真实正文为准，批注/来源标记不会污染章节内容。

### 后端导出边界

`app/services/docx_renderer.py` 的正文节点构造不再把 `missing_information_json` 转换成 DOCX 段落。`validate_document` 和 `Export.has_missing_info` 继续保留，以便导出前校验、工作台提示和审计追踪不丢失。

### 可测试接缝

- 后端：以 `render_to_docx` 公共接口验证缺失提示不出现在 DOCX，同时正文仍正常导出；现有冲突提示行为保持不变。
- 前端：以 TypeScript/Vue 构建作为组件接口、模板和类型检查；通过本地页面验证四个功能栏、批注标识/高亮、来源卡片展开和正文定位。

## 失败与降级

- 批注创建失败：保留表单内容并在右侧显示错误，不生成假批注标识。
- 来源详情加载失败：卡片仍显示引用中的文件 ID、定位和参考原文，并提示文件元数据暂不可用。
- 正文找不到 `target_text` 或 `source_excerpt`：不伪造高亮，回退到章节范围定位并提示用户。
- `missing_information_json` 格式异常：编辑器不阻塞正文，忽略异常提示；导出行为沿用现有安全降级。
- 数据链追踪保持占位，不显示“已完成”或虚构的一致性结果。
