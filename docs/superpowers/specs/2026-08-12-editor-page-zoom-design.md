# 富文本章节页面缩放设计

## 背景

章节正文位于三栏文档编辑页中间的 `.editor-content` 区域，正文由 Tiptap 编辑器渲染在 `.word-page` 内。用户需要在不改变正文格式和导出结果的前提下调整页面预览大小，便于阅读和编辑长章节。

## 目标与边界

- 在章节正文区域提供放大、缩小和重置缩放控制。
- 默认缩放比例为 100%，支持 50%–200% 范围，步进 10%。
- 缩放只影响当前页面的视觉预览，不修改 Tiptap 文档 JSON、正文实际字号、章节保存数据或 DOCX 导出内容。
- 当前不做跨文档持久化，也不调整浏览器整体缩放、左侧目录或右侧数据来源面板。
- 缩放比例始终显示为百分比，达到上下限时对应按钮禁用。

## 交互设计

缩放控件放在章节正文上方的章节操作栏，与保存、确认、重新生成和导出操作同一行。控件按顺序显示：

1. `−`：按 10% 缩小。
2. 当前比例，例如 `100%`：点击后恢复到 100%。
3. `+`：按 10% 放大。

按钮使用明确的 `aria-label` 和 `title`；当前比例按钮使用 `aria-live="polite"`，让辅助技术能感知比例变化。缩放操作不触发 `edit` 事件，也不改变保存按钮状态。

## 技术方案

- 在 `ContentPanel.vue` 内维护视图级 `zoom` 状态，避免把与页面预览有关的状态提升到文档业务状态。
- 使用 `transform: scale(...)` 缩放 `.word-page`，通过 `transform-origin: top center` 保持页面从顶部居中缩放。
- 为缩放后的页面预留对应的布局高度，避免内容缩放后滚动区域高度仍按未缩放尺寸计算，导致页面底部无法完整浏览。
- 提取无 DOM 依赖的缩放工具函数，统一管理最小值、最大值、步长、边界裁剪和百分比标签，便于单元测试。
- 章节切换时保留当前页面缩放比例；组件销毁时状态自然释放，刷新页面回到 100%。

## 验收标准

- 初始页面显示 100%。
- 点击 `+` 后比例增加 10%，点击 `−` 后比例减少 10%，点击比例按钮恢复 100%。
- 比例不会低于 50% 或高于 200%，上下限按钮有禁用状态。
- 页面视觉尺寸随比例变化，正文内容和字号格式没有被写回章节数据。
- 章节保存、确认、重新生成、导出和引用定位现有行为不受影响。
- 前端缩放工具测试、现有前端测试和生产构建均通过。

## 失败场景

- 缩放控件不可用时，正文仍以 100% 正常显示。
- 快速连续点击不会产生越界比例或 NaN 等非法状态。
- 没有章节时不显示缩放控件，空状态页面保持现有布局。
