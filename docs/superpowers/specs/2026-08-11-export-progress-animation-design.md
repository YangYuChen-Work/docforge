# 导出动态进度效果设计

## 1. 背景

当前文档编辑页点击导出后，前端同步等待 `POST /api/documents/{doc_id}/export` 返回，期间没有可见反馈。项目已有导出提示样式，但尚未与导出请求状态连接。导出接口会在服务端完成文件生成后才返回结果，因此本次只增加前端阶段反馈，不把前端动画当作后端真实百分比。

## 2. 目标与边界

### 目标

- 用户选择 DOCX、PDF 或 XLSX，以及是否带批注后，立即看到居中的导出进度卡片。
- 导出等待期间展示清晰的阶段变化和持续动画。
- 成功、校验失败、服务端失败和网络失败都显示明确的最终状态。
- 导出完成后继续使用现有下载地址，不改变导出文件和后端状态模型。
- 导出进行时阻止重复触发，结束后恢复操作。

### 不在范围内

- 不新增后端进度字段、后台任务或轮询接口。
- 不显示没有服务端依据的精确百分比。
- 不修改 DOCX/PDF/XLSX 生成逻辑、导出校验规则或下载接口。
- 不覆盖用户提供的源文件。

## 3. 方案选择

### 方案 A：居中阶段卡片（采用）

使用遮罩层和居中的白色状态卡片，显示格式、当前阶段、循环流动的进度条和状态图标。阶段由前端请求生命周期驱动，语义准确、改动集中，符合当前工程管理风格。

### 方案 B：居中模拟百分比

使用定时器从 0% 递增到 90%，请求完成后跳到 100%。视觉上更直观，但百分比并不代表真实导出进度，容易造成误解。

### 方案 C：居中步骤时间线

只显示三个步骤节点，不使用进度条。表达最保守，但等待期间变化较少，反馈弱于方案 A。

方案 A 在准确性、反馈强度和实现成本之间最平衡，因此采用方案 A。

## 4. 用户体验设计

### 4.1 导出中

点击导出选项后：

1. 关闭导出菜单。
2. 清空上一次导出结果。
3. 打开居中进度卡片。
4. 禁用导出入口，避免同一文档并发发起多个导出请求。
5. 调用已有 `createExport(docId, format, includeComments)`。

卡片内容包括：

- 标题：`正在导出 {FORMAT}`。
- 批注说明：`包含批注` 或 `不含批注`。
- 阶段文字：`准备导出`、`正在生成文件`、`正在准备下载`。
- 阶段指示：三个节点，当前节点使用蓝色，已完成节点使用绿色。
- 进度条：蓝色循环流动动画，仅表示请求仍在处理，不显示百分比。

阶段切换按前端时序进行：

- 打开卡片时进入“准备导出”。
- 请求发出后进入“正在生成文件”。
- 收到成功响应后，在打开下载前进入“正在准备下载”。
- 下载地址打开后进入“导出完成”。

如果后端响应较快，阶段可以直接跳过中间文案，但卡片仍应至少显示一次，避免点击后无反馈。

### 4.2 导出成功

收到成功响应且没有 `error_message` 后，卡片显示绿色成功图标和 `导出完成`，停留短暂时间后调用现有下载地址。下载打开失败仍不伪装成服务端导出失败；页面会保留成功状态，并由浏览器处理下载窗口行为。

### 4.3 导出失败

以下情况统一切换为红色失败卡片：

- 接口返回 `error_message`。
- 导出前校验失败。
- 网络请求异常。

卡片显示 `导出失败` 和可读错误原因，并提供“关闭”操作。校验错误继续复用现有 `validation_report` 的错误和警告信息，不改现有错误解析规则。失败时不打开下载地址。

### 4.4 无障碍与动效降级

- 卡片使用 `role="status"`，阶段变化通过文本可读。
- 动画只承担等待反馈，不承载业务信息。
- `prefers-reduced-motion: reduce` 时关闭循环流动和进入动画，保留静态阶段指示。
- 遮罩层不允许误触编辑区，但关闭失败卡片后可继续编辑。

## 5. 实现边界与状态模型

前端在 `DocEditor.vue` 内维护导出状态，沿用当前页面的导出入口和 API 模块：

```text
idle
  └─ doExport → preparing
                  └─ request sent → generating
                                      ├─ success → preparing-download → completed → idle
                                      └─ failure → failed → idle
```

建议状态字段：

- `exportState`: `idle | preparing | generating | preparing-download | completed | failed`
- `exportFormat`: 当前导出格式
- `exportIncludeComments`: 是否带批注
- `exportError`: 当前失败原因

状态只服务于当前页面反馈，不持久化到数据库。`createExport` 和 `getExport` API 不需要修改；本次不使用 `getExport` 轮询。

样式放在现有文档页样式文件中，新增居中遮罩、卡片、阶段节点、循环进度条和状态变体。命名使用导出专用前缀，避免影响已有导出菜单和其他页面。

## 6. 测试设计

### 前端行为测试

- 导出选项触发后，页面源代码包含导出状态的准备、生成、准备下载、成功和失败分支。
- 导出请求期间重复导出入口处于禁用状态。
- 成功响应不会在 `error_message` 存在时打开下载地址。
- 校验失败能展示校验报告中的错误或警告。
- 网络异常能展示错误原因并恢复可操作状态。
- 居中进度卡片包含 `role="status"` 和减少动效媒体查询。

测试优先验证用户可见行为和请求结果处理，不测试具体 CSS 像素值或定时器内部实现。

### 验收命令

```powershell
Set-Location frontend
npm run build
node --test tests\*.test.mjs
```

现有后端测试不需要因本次纯前端交互改动而扩展，但完成实现前仍运行前端构建和全部前端测试；若构建或测试发现与现有代码相关的回归，再补充最小修复。

## 7. 验收标准

1. 三种格式的导出都能显示居中动态进度卡片。
2. 卡片至少能展示准备、生成和完成/失败三类状态。
3. 等待期间有循环动画，但没有虚假的精确百分比。
4. 成功时仅在服务端导出成功后打开下载地址。
5. 任意失败都显示明确原因，不显示成功，不打开下载地址。
6. 导出期间不能重复发起导出，结束后恢复操作。
7. 动效遵守 `prefers-reduced-motion` 降级规则。
8. 不改变后端导出 API、文件生成逻辑和源文件。
