# 乐造 OS 融合式前端风格重构设计

## 1. 设计目标

在不改变后端逻辑、数据库、API 路径、请求参数和响应结构的前提下，重构项目文档工作台的前端视觉系统。新界面参考乐造 OS 的工业软件表达，同时保留本项目以文档生成、来源追溯和人工确认为核心的业务特征。

本次重构以 1024px–1920px 桌面工作台为验收范围，重点解决以下问题：

- 当前页面画布、工作面和导航之间的层级偏弱，业务区容易显得松散。
- 列表、配置、审计和向导页面的控件密度与对齐规则不完全一致。
- 编辑器在较窄桌面宽度下容易出现三栏互相挤压。
- 深色模式与浅色模式需要共享统一的视觉语法，避免直接反色造成生硬切换。
- 全局风格升级不能引发局部错位、撑爆、基线不齐或滚动职责混乱。

## 2. 调研记录

### 2.1 调研范围

使用真实浏览器访问乐造 OS，选择“海洋事务行业”租户后抽样以下界面：

- 登录页；
- 通用桌面首页；
- 项目管理列表；
- 查询与高级筛选区；
- 项目表格与分页区；
- 新建项目集右侧侧滑表单。

同时抽样本项目以下页面：

- 项目文档列表；
- 新建文档向导；
- 文档助手配置；
- 日志审计；
- 三栏文档编辑器。

浏览器调研产物保存在本地 `output/playwright/lzos-reference/` 与 `output/playwright/current-ui-audit/`，这些运行时截图不纳入 Git。

### 2.2 乐造 OS 的可复用风格特征

- 深青蓝导航承担品牌与模块定位，白色业务工作面承担高密度操作。
- 主色集中用于导航、表头、当前项和主操作，业务状态使用有限的辅助色。
- 页面采用低圆角、细边框和较少阴影，空间主要依靠分隔线和明度差组织。
- 工具栏、查询区、表头、数据行和分页形成严格的纵向节奏。
- 列表表头具有明显的冷蓝色层级，数据行紧凑但不拥挤。
- 右侧侧滑表单使用稳定的标签列、输入列和固定底部操作区。
- 局部容器独立滚动；顶部导航、左侧导航和底部操作不会被内容推走。
- 桌面端优先展示更多业务信息，不用夸张留白或营销式卡片抢占工作空间。

### 2.3 不直接复制的部分

- 不引入乐造 OS 的底部应用坞，因为本项目不是多应用门户。
- 不复制其品牌、插图、头像、图标资源或业务文案。
- 不将所有表头改成高饱和蓝；文档工作台需要更克制的长时间阅读体验。
- 不为追求视觉相似而改写现有路由、业务状态或 API。

## 3. 设计方向

采用“融合式重构”：保留现有 Vue 组件、业务流程和信息架构，引入乐造 OS 的工业工作台层级、控件密度和对齐纪律，并保留本项目的文档纸张、来源引用、待补充状态和三栏编辑体验。

视觉结构为：

1. 深色导航框架负责全局定位；
2. 冷灰蓝画布负责承托内容；
3. 白色或深蓝灰工作面负责业务操作；
4. 文档纸张作为独立语义层，不与普通卡片混用；
5. 状态色只表达业务状态，不承担装饰职责。

## 4. 主题系统

### 4.1 浅色主题

| 语义 | 建议值 | 用途 |
|---|---:|---|
| 画布 | `#eef3f6` | 页面背景 |
| 主工作面 | `#ffffff` | 表格、详情、筛选和表单 |
| 次工作面 | `#f5f8fa` | 表头、分组、禁用面 |
| 导航 | `#086783` | 左侧主导航 |
| 导航深色 | `#07546b` | 悬停、按下和品牌区 |
| 主操作 | `#2e8eae` | 主按钮、当前标签和焦点 |
| 主操作浅色 | `#e5f3f8` | 选中行、信息提示 |
| 主文字 | `#132a35` | 标题和正文 |
| 次文字 | `#58707c` | 辅助说明 |
| 弱文字 | `#81939c` | 占位符和禁用说明 |
| 分隔线 | `#cbd8de` | 普通边框 |
| 强分隔线 | `#afc1ca` | 表头和结构边界 |

### 4.2 深色主题

深色主题与浅色主题保持相同语义层级，不做机械反色：

| 语义 | 建议值 | 用途 |
|---|---:|---|
| 画布 | `#0d171d` | 页面背景 |
| 主工作面 | `#16242b` | 表格、详情、筛选和表单 |
| 次工作面 | `#1d3039` | 表头、分组、禁用面 |
| 导航 | `#083f53` | 左侧主导航 |
| 导航深色 | `#062f3e` | 悬停、按下和品牌区 |
| 主操作 | `#61b6d2` | 主按钮、当前标签和焦点 |
| 主操作浅色 | `#1c3c48` | 选中行、信息提示 |
| 主文字 | `#e7f0f3` | 标题和正文 |
| 次文字 | `#a8bcc5` | 辅助说明 |
| 弱文字 | `#718893` | 占位符和禁用说明 |
| 分隔线 | `#2b424d` | 普通边框 |
| 强分隔线 | `#3b5864` | 表头和结构边界 |

成功、警告、错误和待补充状态分别使用低饱和绿、琥珀和红色。每种状态同时定义文字色、背景色和边框色，不能仅靠颜色区分。

文档编辑器中的纸张在浅色主题使用暖白色，在深色主题仍保持低亮度暖灰白纸面，确保 DOCX 所见即所得和正文可读性。纸张之外的工具栏、章节树和证据面板遵循当前主题。

### 4.3 主题切换

- 背景、边框、文字和阴影使用约 240ms 的统一过渡。
- 不对宽度、高度、网格轨道和纸张尺寸做主题切换动画。
- 切换后焦点、悬停、禁用和业务状态保持相同层级。
- 支持 `prefers-reduced-motion`，关闭非必要位移和渐显。

## 5. 排版、图标与空间

- 使用本地中文无衬线字体栈，不增加网络字体依赖。
- 品牌“徐工重型”保留现有楷体识别，正文和功能区不使用楷体。
- 页面主标题控制在 28–32px，模块标题控制在 16–18px，正文以 13–14px 为主。
- 数量、日期、进度和实体 ID 使用等宽数字或 `tabular-nums`。
- 输入框和按钮高度统一为 34–36px；表格数据行约 42px。
- 外层容器使用 8px 左右圆角，输入框和小按钮使用 3–5px 圆角，状态标签使用低圆角矩形。
- 图标保持统一线宽和光学尺寸，不新增图标库。
- 阴影只用于浮层和侧滑面板，普通工作面依赖边框与明度差。

## 6. 应用壳层

- 左侧导航改为深青蓝，品牌区、模块区、配置区和主题开关形成稳定纵向层级。
- 当前页面使用浅色高亮块、左侧强调线和较高字重共同标识。
- 导航展开宽度保持适合中文标签的范围；折叠态保留图标、提示和可见恢复按钮。
- 主内容区在 1440px 附近使用约 24px 内边距；1024px 使用约 16px；1920px 限制有效内容宽度，避免表格与文字无限拉伸。
- 编辑器路由继续使用全宽工作区，不继承普通页面的最大宽度和外边距。

## 7. 页面设计

### 7.1 项目文档列表

- 页面顺序保持“统计概览—筛选与分类—文档表格—右侧辅助信息”。
- 统计区改为连续分栏，强调当前文档总量和关键状态，取消营销卡片感。
- 表格置于主工作面中；表头使用次工作面背景和强分隔线。
- 标题列保留最大可用空间，状态、日期和操作列保持稳定宽度。
- 右侧辅助栏包含新建入口、项目搜索和常用模板。
- 宽度不足时表格在自己的容器内横向滚动，操作列保持可见；不允许页面根节点横向撑爆。

### 7.2 新建文档向导

- 三个步骤使用紧凑编号轨道，当前、完成和未开始状态明确。
- 项目、模板和资料使用统一的可选择行结构，标题、编号、阶段和状态保持基线对齐。
- 右侧生成前确认区独立成工作面，显示已完成条件与下一步动作。
- 1024px 下压缩间距和辅助栏宽度，项目名称最多形成可读的两行，不拆成碎片化多行。

### 7.3 文档助手配置

- 模板列表与详情形成主从布局；列表宽度受控，详情区自适应。
- 模板分类、启用状态和章节数量使用稳定列对齐。
- 章节列表按序号、标题、必填状态和资料类型组织。
- 未选模板时使用结构化空状态，不保留大片无意义留白。

### 7.4 日志审计

- 指标使用连续数据栏，筛选条件进入统一工具条。
- 表头吸顶，表格主体独立滚动，分页固定在表格工作面底部。
- 长实体 ID 使用等宽字体和省略显示，悬停显示完整值。
- 1024px 下允许表格横向滚动，不压缩时间、结果和操作列至不可读。

### 7.5 文档编辑器

- 1440px 及以上维持“章节树—文档纸张—来源/批注/生成建议”三栏同时展示。
- 低于约 1180px 时主导航进入窄栏，右侧证据面板改为可唤出的侧滑面板；章节树与文档纸张保持主工作区。
- 编辑工具栏允许自身横向滚动，不换成多行，不推动正文区域下移。
- 文档纸张区域独立滚动；章节树和证据面板各自管理纵向滚动。
- 保存、重新生成、导出和一键确认保持现有业务行为，仅统一位置、尺寸和状态反馈。

### 7.6 弹窗与侧滑面板

- 简单确认继续使用小弹窗。
- 复杂表单、来源详情和设置优先使用右侧侧滑面板。
- 表单使用稳定标签列和输入列；必填标记与标签处于同一基线。
- 面板底部操作区固定，表单主体独立滚动。

## 8. 响应式规则

| 宽度 | 应用壳层 | 普通页面 | 编辑器 |
|---|---|---|---|
| 1024–1179px | 窄导航优先 | 缩小间距；局部横向滚动 | 证据面板侧滑；章节树与纸张并列 |
| 1180–1439px | 可展开导航 | 主从布局压缩辅助栏 | 三栏紧凑展示或按可用宽度侧滑证据面板 |
| 1440–1599px | 完整导航 | 标准工作区间距 | 三栏完整展示 |
| 1600–1920px | 完整导航 | 限制有效内容宽度 | 增加纸张周围呼吸空间，不无限加宽文本 |

所有断点都必须满足：

- 页面根节点没有非预期横向滚动；
- 表格只在表格容器内横向滚动；
- 标题、输入框、按钮和表头保持基线对齐；
- 文字不覆盖图标或操作区；
- 编辑器各栏不互相抢占滚动和宽度；
- 浅色与深色切换不改变布局尺寸。

## 9. 状态与可访问性

- 加载状态保持最终组件尺寸，减少内容返回后的布局跳动。
- 空状态放在对应工作面内，给出当前原因和可执行动作。
- 错误状态使用明确文字，不依赖全屏提示或假成功。
- 主按钮、次按钮、文字按钮和危险按钮分别定义悬停、按下、焦点和禁用状态。
- 键盘焦点保持清晰可见；主要滚动容器具有可访问名称和可聚焦入口。
- 状态标签同时包含文字，不能只用颜色或图标表达。

## 10. 技术边界

- 允许修改：`frontend/`、前端测试和本设计相关文档。
- 禁止修改：`backend/`、数据库、迁移、后端测试、API 路径、请求参数和响应结构。
- 保留现有 Vue 3、Vite、Pinia、Vue Router、Tiptap 和原生 CSS 技术栈。
- 不增加 UI 框架、图标库或网络字体依赖。
- 只在布局职责不清时做小范围前端组件拆分，不重写业务状态管理。

## 11. 测试与验收

自动化测试先于生产样式和组件行为修改，覆盖：

- 浅色与深色主题令牌完整性；
- 导航展开、折叠和窄屏行为；
- 编辑器窄屏证据面板；
- 表格滚动容器和关键控件尺寸；
- 减少动画偏好；
- 现有前端交互回归测试。

浏览器验收覆盖文档列表、新建向导、配置、审计和编辑器，并在 1024、1280、1440、1600、1920px 下分别检查浅色和深色模式。最终执行：

```powershell
Set-Location frontend
npm run build
node --test tests\*.test.mjs
```

同时使用 Git 确认变更中没有 `backend/` 文件。

## 12. 完成标准

- 五个核心页面形成统一的工业工作台视觉语言。
- 深色模式与浅色模式层级一致，切换自然且无布局跳动。
- 1024px–1920px 范围内无错位、覆盖、非预期撑爆或滚动冲突。
- 文档编辑器在窄桌面宽度下仍保留可用的章节导航和纸张阅读空间。
- 所有现有前端功能、路由和 API 调用保持兼容。
- 前端构建和全部前端测试通过，Git 变更不包含后端逻辑代码。
